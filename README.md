# BRBYPASS

Пакетный ретранслятор SA-MP <-> Black Russia. Стоит посредником между обычным SA-MP клиентом и сервером Black Russia: гоняет через себя буквально каждый пакет — расшифровывает, разбирает RakNet-фрейминг, перекладывает в формат другой стороны и отдаёт дальше.

## Схема

```
+-----------------------+     +-------------------+     +-----------------------+
|                       |     |                   |     |                       |
|     SA-MP Client      |<--->|     BRBYPASS      |<--->|   Black Russia        |
| (обычный клиент)      |     | (UDP relay)       |     |   Server              |
|                       |     |                   |     |                       |
+-----------------------+     +-------------------+     +-----------------------+
          |                             |                          |
          |                             |                          |
          v                             v                          v
   SA-MP протокол,            Конвертация ID,            Кастомный RakNet
   шифр портом                перекодировка              + шифрование
   назначения                 utf-8 -> cp1251 и др.
```

## Что делает
1. Принимает SA-MP клиента на локальном порту и ведёт отдельную сессию к реальному BR-серверу.
2. Расшифровывает трафик с обеих сторон (SAMP — шифр от порта назначения, BR — своё шифрование) и разбирает RakNet-фрейминг: датаграммы, ACK/RangeList, InternalPacket'ы (reliability, ordering, сплиты), RPC-кадры (9-битные ID у BR против 8-битных у SAMP).
3. Пересобирает каждый пакет под стандарт другой стороны: клиенту отдаёт пакеты со стандартным SAMP RakNet-заголовком, серверу — в BR-фрейминге. Ведёт нумерацию сообщений, батчит ACK и ретраит reliable-пакеты на обоих плечах.
4. Конвертит содержимое: ID пакетов/синков/RPC (таблица — в [RPCS.md](RPCS.md)), packing полей синков, текст BR (utf-8) в cp1251 для клиента (чат, диалоги, текстдравы, 3D-тексты, чат-бабблы).
5. Отвечает клиенту локально там, где протоколы расходятся (экран выбора класса/спавна, ConnectionRequestAccepted).
6. Опции релея через `config.ini`: игнор дамага (`damage_ignore`), дроп `TogglePlayerControllable`.
7. Пакеты с префиксом `SAMP` (`53 41 4D 50`) в начале датаграммы пересылает как есть, без разбора, в обе стороны.
8. Всё неизвестное не роняет, а дропает с логом (`no SAMP mapping` / `no BR mapping`).

## Чего не делает
1. Не защищает от DDoS и не прячет сервер — это конвертер протоколов, а не прокси-щит.
2. Не знает все BR RPC. Неопознанные ID дропаются (их видно в логе, список частых — в [RPCS.md](RPCS.md)).
3. Не эмулирует игровой клиент: кастомные BR-интерфейсы (кейсы, донат-меню, tuning) показывает заглушками/текстом, а не окнами.

## Требования
1. Python 3.10+ (только стандартная библиотека, `pip install` ничего не надо).
2. Доступность UDP до BR-сервера с хоста, где запущен байпасс.
3. SA-MP клиент, направленный на `listen_host:listen_port` байпасса.

## Как настроить / запустить
1. Открой `config.ini` и поменяй под себя:
   - `[Bypass]` — `listen_host`/`listen_port`, куда коннектится SA-MP клиент (по умолчанию `127.0.0.1:7777`);
   - `[BlackRussia]` — `host`/`port` реального BR-сервера (все ID серверов: https://www.blast.hk/threads/258267/);
   - `[Auth]` — `password`, `auth_auto`/`reg_auto`, `email`, `referral`, `gender`, `skin`;
   - `[Relay]` — `toggle_player_controllable`, `damage_ignore` (хп всегда 100: `SetPlayerHealth`/`SetPlayerArmour` ниже 100 дропаются).
2. Запусти `python main.py` (или `python main.py --config path/to/config.ini`). Если `config.ini` нет — стартует на дефолтах.
3. Подключи SA-MP клиент к `listen_host:listen_port`. Дальше авторизация/регистрация идут через релей.

## Настройка клиента (важно)
1. Сборка карты Black Russia конца 2021 года: https://drive.google.com/file/d/1QKSxwn95iI_o5gD1O29WLA86E0IkMfzN/view
2. **Чтобы диалоги нормально работали — удали `dialogs_1.asi`.** Также рекомендуется удалить `chat.asi`.

## Известные проблемы
1. Часть BR RPC не опознана и дропается: `323`, `343`, `364`, `388`, `391`, `447` (видно в логе как `no SAMP mapping`). По мере разбора вайра добавляются в `RPCS.md`.
2. `SET_PLAYER_NAME (384)` в живом пути не релеится (обработчик есть только в неиспользуемом `relay/world_rpc.py`).
3. Ответы на диалоги идут через gui-10 JSON `{"r","i","l"}`; экзотические формы диалогов могут требовать другого формата.

## Обратная связь
Нашёл неопознанный RPC (строка `no SAMP mapping` / `no BR mapping` в логе) — кидай ID, размер и hex пейлоада. PR с новыми маппингами приветствуются, формат — по существующим веткам в `relay/relay.py` (ID только из `br_side/constants.py` / `samp_side/constants.py`).
